### 8.3 `check:context-budget` — the growth guard, in two halves

> **`check:context-budget` does not exist**, in either half — it went in the 2026-08-10 apparatus
> cut and the corpus came back on 2026-08-11 without it (`CLAUDE.md`). No ceiling is enforced, and
> `pnpm check:context-budget --sessions` is not a command. §8.1's index, which the paragraph below
> credits for making a section's cost visible, is gone too.

**What it is for.** The corpus is consulted on every task and it is consulted well — §8.1's index
made a section's cost visible, and 94% of governance reads already scope themselves with
`offset`/`limit`. What is not self-correcting is **growth**: `__internal__` went 790 KB → 969 KB
across five implementation commits in a single day, and two commits written while the plan against
that growth was being approved added 17 KB more, 97% of it into one section — one of the two being a
pure rename with no new behaviour. A ceiling is the only thing that turns *keep these small* into
something that fails a build.

**Two halves, and only one of them is enforcement.** The static half runs in the `verify` job on
every push. The transcript half reads machine-local session logs, cannot run in CI, and is
registered as `definition-of-done.md` §7.9 — a convention with a runnable aid. **They are one
script with a flag rather than two scripts** so that the census counts one name: a second
`check:*` that CI never runs is precisely what §7b exists to stop.

**Sizes are UTF-8 bytes**, measured by `doc-index.mjs`'s `sizeInBytes` — the same function the index
is generated with. Two measures would let `INDEX.md` and this check report one section at two sizes,
and a reader who planned an edit against the smaller one would be failed by the larger. The corpus
is full of `—`, `§` and `≈`, where a JavaScript string counts one and UTF-8 spends two or three; on
a ledger entry that gap is 2%, which is 550 bytes against a 25 KB ceiling.

#### 8.3.1 The static half

**Input.** `readIndexableDocuments` over `__internal__` — the same set §8.1 indexes, for the same
reason — plus `CLAUDE.md`. A file with no numbered heading is not a unit, which is `renderIndex`'s
selection rule reused rather than restated: nothing cites the design notes under `zag-solid/`,
`upstream/` or `internal-test-utils/`, and a ceiling on a file nobody consults is a ceiling on the
wrong thing.

**Three units, three ceilings, because a citation costs whatever the unit it names costs:**

| Unit | Ceiling | Why that unit |
|---|---|---|
| A `##` section of any indexed document | **25 KB** | `` `plan.md` §3 `` is a citation someone writes, and it costs the whole nested span |
| A **sharded file** — `decisions/3.13-…`, `testing/8.02-…` | **25 KB** | Its heading is a `###`, so the section rule never sees it. A shard is one citable unit exactly as a section is |
| `CLAUDE.md` | **16 KB** | The one file read in full on every task before anything is asked |

**Where 25 KB comes from, and why it is not raised.** Measured across the eleven documents, a `##`
is 4.6 KB at p50 and 11 KB at p90, so the ceiling sits at **2.3× p90** — the size at which a section
stops fitting one targeted read and starts being grepped-and-guessed instead. It is not fitted to
what exists. **A ceiling raised to accommodate the corpus is a ceiling that gets raised again, which
is a deleted one**, so the remedy when a unit reaches it is always structural: its parts become
files, the way `decisions-ledger.md` §3's entries did and `testing.md` §8's check definitions after them.

**The three tight cases are named on every green run, not exempted.** They pass:

| | now | ceiling | headroom |
|---|---|---|---|
| `CLAUDE.md` | 15.6 KB | 16 | 0.4 KB |
| `decisions/3.13-s3-styling-seam.md` | 23.3 KB | 25 | 1.7 KB |
| `component-blueprint.md` §11 | 20.9 KB | 25 | 4.1 KB |

The success line prints the three closest to their ceiling with the room each has left, because **a
ceiling nobody sees approaching fires on an ordinary edit, and a ceiling that fires on an ordinary
edit gets argued with.** The day `component-blueprint.md` §11 needs another paragraph, its `###`
subsections become files under `component-blueprint/` and the anchor `` §11.3 `` keeps resolving —
`readIndexableDocuments` recurses and `buildAnchorResolver` folds `<name>/**` into `<name>.md`, both
written as general rules with no path named, so that shard costs no script change. That is not a
forecast: it is what `decisions-ledger.md` §3 and `testing.md` §8 already did, and neither move touched a
script.

**The allow-list.** `context-budget.config.ts` at the repo root, one row per shard permitted over the
ceiling: the file, **the size the exception was granted at**, the reason, and what deletes the row.
Four failures come out of it, and the last three are what make it a register rather than a list of
excuses:

- a shard over the ceiling with **no row** — `oversized-shard`;
- a shard that has **grown past the size its row was granted at** — `allowance-outgrown`. A row is
  an exception at a measured size, not a licence to keep growing;
- a row whose file is **back inside the ceiling, or gone** — `stale-allowance`. An exception nobody
  re-derives is a permanent hole in the rule it excepts, and this is the arrangement that makes
  someone notice;
- a row **missing a field** — `malformed-allowance`, and it stops the run before any ceiling is
  judged. `BudgetAllowance` is an interface, but the root `tsconfig.json` sets `"files": []`, so
  **no `tsc` pass in this repo reads a root config file** — this one or `attribution.config.ts`. A
  row without `ceilingBytes` would compare against `undefined`, be false, and grant its file
  unlimited growth in silence, which is the register's own failure mode. The shape is therefore
  checked at runtime rather than assumed from the type.

**It is a config file and not a table in this document**, and the reason is the reader. The two
registers it is modelled on — the axe allowances (`definition-of-done.md` §5) and the coverage
allow-list (§6) — are prose because their checks do not exist yet and a person is the only reader.
The precedent for a register a script reads is `attribution.config.ts`: checked in, the rule stated
once beside the data. A hand-parsed markdown table would put a second grammar between the rule and
its enforcement, and its characteristic failure is the one above — a malformed row skipped rather
than reported. **Contents live there and only there**; `definition-of-done.md` rule 1.13 says when
the check must pass and never what is in the register.

**Failure output.** Grouped by fault kind, each group headed by what that kind *means* and what
repairs it, then one `unit — detail` per fault. Grouped rather than in file order for §8.2's reason:
the kinds have different fixes, and *shard this section* is not the same instruction as *delete this
row*.

**Blind spots, three:**

- **It bounds size and says nothing about density.** A 24 KB section of restated rules passes; a
  9 KB one that is entirely pointers passes identically. The check measures what a consultation
  costs, never whether the bytes earned their place.
- **A `##` at 24.9 KB is a pass, and a citation to it still costs 24.9 KB.** The ceiling is where a
  unit becomes intolerable, not where it becomes cheap. The number that measures *cheap* is the
  transcript half's, and it is not a gate.
- **Nothing enforces the number of units.** Fifty sections of 20 KB satisfy every rule here while
  the corpus doubles. The ceiling guards the tail the measurement found; it does not guard the
  total, and no artefact in this repo does.

#### 8.3.2 The transcript half — `pnpm check:context-budget --sessions`

**Input.** `~/.claude/projects/<repo-slug>/*.jsonl`, or `--transcripts=<dir>`. **This is why it
cannot be a gate:** the transcripts are machine-local, not in the repo, and no CI runner has them. A
missing directory or an empty one **fails loudly** rather than reporting a median over zero sessions.

**Algorithm.** Read each transcript in file order, which is the order the turns happened in. Match
every `Read` `tool_use` to its `tool_result` by id and sum the bytes the result actually returned —
what entered the context, not the file's size on disk. Attribute each read to the phase its
**request** falls in, before or after the session's first `Edit`/`Write`, because the request is the
decision being measured. Then take the median of the governance bytes in the pre-edit window.

**A governance read is `CLAUDE.md` or a `.md` under `__internal__`**, frozen at the plan's own
definition. Widening it would produce a number that is not comparable to the figure it is measured
against, and an incomparable before/after is worse than no measurement. Skill reads are counted and
reported **separately** for that reason.

**Two n's are printed, and the second is the one the median is over.** A session that never reached
an edit has no *before the first edit*; folding its whole governance bill in would measure a
different thing under the same name. **A number quoted without its n is the failure
`prior-art.md` §0.4 is about**, one convention over.

**Blind spots, and the first is a finding rather than a limitation:**

- **The plan's 137 KB baseline is not reproducible.** Run over the transcripts on disk, this script
  gets **108.6 KB** under the definition the plan states; widening to every `.md` read gives 114.5 KB
  and to every read of any file 155.7 KB. None of the three is 137. So the figure is printed as a
  **quotation, not a baseline** — the output says so — and *"137 → N"* is not a delta anyone may
  write. What the re-derivation does reproduce is every other row of the plan's §1.1: 76% governance
  share against 77%, 94% scoped reads against 95%, worst two 387/307 KB against 383/304. The
  measurement is the same measurement; the headline is the one figure it disagrees with.
- **It cannot attribute a change to any one step.** The index, the shard and the skills all landed
  inside one day, into one transcript corpus, and nothing separates their effects. The skills'
  −30 to −55 KB was labelled an **estimate** by the plan and it stays one: four post-change
  transcripts is not a measurement, and one of the four is a phase session that read the plan whole.
- **The corpus is biased upward by the work that produced it.** The transcripts here are mostly
  document-writing sessions, which read governance documents by definition. A run of ordinary
  component work would measure something different, and there is none yet to measure.
- **Transcripts are not immutable and the historical set is not reconstructible.** They are appended
  to after the fact, so *the 23 files that existed on 08-09* cannot be recovered by any ordering
  available today. Every re-run measures the corpus as it now stands.
